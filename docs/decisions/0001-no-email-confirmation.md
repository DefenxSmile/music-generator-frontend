# ADR-001: Регистрация без подтверждения почты

## Status

Accepted. В Java еще не сделано.

## Date

2026-10-23

## Context

Онбординг должен довести человека до первой готовой песни без лишних шагов. Подтверждение почты ставит между регистрацией и песней письмо и чужую HTML-страницу API. Это удлиняет путь до ценности.

Сейчас `POST /api/v1/auth/register` не открывает сессию и шлет письмо. Пока почта не подтверждена, API отвечает `403 EMAIL_NOT_VERIFIED`. Экран приложения для этой ссылки не нужен и в целевой путь не входит.

Вход продукта — только Яндекс и VK, без своего пароля и без Google на этом шаге. Кнопки уже на экране. Сессию они откроют, когда Java начнёт эти редиректы. Свой бэкенд пользователей не заводим.

## Decision

Подтверждение почты и свой пароль не часть онбординга и не экраны этого репозитория. Человек входит через Яндекс или VK и сразу продолжает путь к первой песне.

## Alternatives Considered

### Оставить письмо как сейчас

Плюс: API уже так умеет. Минус: человек уходит из приложения до первой песни. Отклонено.

### Подтверждать почту позже, после первой песни

Плюс: письмо не блокирует активацию. Минус: это все еще лишний шаг, а целевой вход все равно социальный. Отклонено как постоянное решение. До смены API шаг просто не показываем в целевом пути.

## Consequences

- Контракт в `docs/intent/java-api.md` по-прежнему описывает verify, потому что Java его еще требует. Целевой поток ему не следует.
- Фронтенд не может один убрать блок: генерация без подтвержденной почты получит `403`.
- Кнопки Яндекс и VK на экране есть. Сессию открывает только Java, этих маршрутов в API ещё нет.
