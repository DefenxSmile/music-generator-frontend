# Продукт

Сервис генерации музыки для рынка СНГ, по задаче близкий к Suno. Человек описывает идею или вставляет свой текст, выбирает жанр и стиль, получает песню. Дальше песню можно править, улучшать и скачивать. Список конкурентов в этот документ еще не внесен.

Пользователь, регистрация, кредиты и генерация живут в Java. Этот репозиторий рисует экраны. Оплаты в Java нет. Стартовый грант 0, генерация стоит 1 кредит. Цены с лендинга в приложение не переносить.

## Хосты

Лендинг и приложение — разные хосты одного домена. Лендинг на корне, это приложение на поддомене `app`. Название продукта и домен еще не выбраны. Переход с лендинга — ссылка на приложение, не маршрут внутри лендинга.

Идея и согласие приходят параметрами этой ссылки. `localStorage` и куки корня приложению не видны: это другой origin. GitHub Pages остается тестовым адресом, не боевым хостом.

## Четыре итерации

Итерация 1, текущий запуск. Генерация песни в подарок: текст и музыка. Человек описывает идею или вставляет свой текст и получает два варианта с вокалом. Креатор или бизнес может зайти, но отдельные фичи для них в эту итерацию не входят. Короткий путь: идея, регистрация, первая готовая песня. Подтверждение почты в этот путь не входит. Решение: `docs/decisions/0001-no-email-confirmation.md`.

Итерация 2. Каверы и свой голос.

Итерация 3. Ориентир сдвигается к подписке и креаторам. Появляются фичи дистрибуции музыки на площадки. Оплаты в Java по-прежнему нет, поэтому экран подписки не рисуется, пока её нет в API.

Итерация 4. Продукт ближе к комбайну: обложка для песни, видео для клипа, видео для соцсетей. Оживление фото в эти итерации не входит.

Редактор, выдача файла, каверы, свой голос, дистрибуция, обложка и видео не входят в экраны итерации 1.

## Каналы продаж

Сначала тест Яндекс Поиска. Обязательно три канала: контент в TikTok, Instagram и YouTube, SEO вместе с GEO, и работа с креаторами и инфлюенсерами как с амбасадорами, по сути рефералка. Затем ИИ-артисты, в идеале разные под разные ниши. ИИ-аватары под этих артистов пока идея, не шаг плана.

## Активация и оплата

Активация: человек услышал первую готовую песню. Слушать можно сразу. Paywall открывается, когда человек нажимает «Скачать», и ведет на тарифы. На `/plans` три карточки как на лендинге. Пока оплаты в API нет, файл не отдается и выбор тарифа ничего не списывает.

Квалификация — два вопроса отдельным шагом после первого входа, не на экране входа и не в форме генерации. «Кто вы?»: обычный пользователь, креатор, владелец бизнеса, музыкант. «Для кого песня?»: себе или в подарок. Java не отличает регистрацию от повторного входа, поэтому браузер запоминает, что шаг уже был. Следующий «Войти» окно не открывает. Ответы не блокируют первую песню и в API не уходят.

Снимок лида пишется в браузер на идее, на открытии входа, после вопросов и при запуске песни. В нём идея, ответы, первое касание кампании и `java_user_id`, когда он уже известен. YouGile, Excel и пиксель Яндекс Метрики позже читают этот снимок. В этой задаче их нет: воркер не создаётся, пиксель не ставится, снимок в Java не уходит.

Метрика и GTM не ставятся, пока нет отдельного решения. Когда решение появится, смотреть долю дошедших до первой готовой песни и время до этого момента. Пиксель учит кампанию по этим же шагам снимка, не по отдельной схеме.

## Экраны

Пока человек не вошел: лендинг с идеей, затем главная приложения. На главной только поле идеи. «Создать» открывает `/create` и песню не запускает. Текст с главной всегда попадает в стиль и идею. Текст песни добавляют или генерируют уже на `/create`. На `/create` слева две секции с подписью внутри, справа выбранная песня. «Сгенерировать текст» открывает окно: слова появляются в нём, «В песню» переносит их в поле текста. Пустой текст значит, что слова напишет генерация вместе с музыкой: отдельного запроса «только текст» в Java нет. Вход не отдельный экран: окно поверх `/create` открывают «Создать песню», «Войти», список и тарифы. В окне только две кнопки: Яндекс и VK. Почты, пароля, письма и восстановления пароля нет. Google в этот шаг не входит. После входа, до песни, два вопроса открываются отдельным окном поверх текущего экрана. Ответы не обязательны.

Java такой вход ещё не отдаёт. В собранном приложении кнопка открывает `/api/v1/auth/oauth/yandex` или `/api/v1/auth/oauth/vk`. После успеха сервер ставит refresh cookie и возвращает на `/oauth/callback`, откуда человек попадает к песне. В `next dev` клик не уходит в Java: открывается локальная сессия того же пути, баланс остаётся 0.

После входа: создать песню, карточка песни, список своих песен, тарифы после первой готовой песни.

Разделы живут в боковом меню: Главная (`/`), Создать (`/create`), Мои песни, Тарифы. «Создать видео» (`/video`) и «Релиз» (`/release`) тоже в меню, с меткой «Скоро»: это страницы-ожидание, без клипа и без выпуска на площадки. Новая страница — новый пункт. Админские экраны, когда появятся, отдельным блоком того же меню. На возврате из входа меню скрыто. Окно с вопросами лежит поверх страницы, меню под ним остаётся.

В коде: поле идеи на `/` без вопросов и без ленты примеров. Ссылка лендинга открывает эту страницу, текст из `idea` сразу стоит в поле. «Создать» открывает `/create`: описание остаётся в стиле и идее, поле текста пустое, пока человек сам его не заполнит или не сгенерирует. Окно входа не уводит с `/create`. После сессии окно с «Кто вы?» и «Для кого песня?» открывается поверх страницы, куда человек шёл. Старый адрес `/auth/qualify` только возвращает туда. Старые адреса `/auth` и `/auth/login` открывают то же окно на главной. `/auth/register` открывает поле идеи. На готовой песне «Скачать» открывает paywall и ссылку на `/plans`. Прослушивание paywall не открывает. На `/create` при пустом балансе «Создать песню» открывает поверх страницы те же тарифы, что на `/plans`.
