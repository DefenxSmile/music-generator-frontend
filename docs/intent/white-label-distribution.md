# White-label дистрибуция

Документ для итерации 3: выпуск готовой песни на площадки. Свой дистрибьютор с нуля не строим. Берём B2B white-label / distribution API под своим брендом.

Связанные экраны: `/release` (черновик и выбор площадок уже в UI; «Отправить» выключен, пока нет партнёра и Java-контракта). Продуктовый план: `docs/intent/product.md`.

Дата черновика: 2026-10-28.

## Решение

Не писать собственный пайплайн доставки в Spotify / Apple / Яндекс и т.д.  
Доставку закрывает партнёр (white-label / distribution API / лейбл-аккаунт).  
**Права на трек — у пользователя.** Наш бренд на площадках не обязателен: нужен канал доставки и лицензия от юзера на отправку.

DistroKid, TuneCore, CD Baby, Symphonic, Ditto в классическом виде — дистриб под *их* брендом для артистов. Их можно рассматривать только если устраивает уход юзера из приложения; для кнопки «Выпустить» внутри продукта удобнее API-партнёр.

## Юридическая модель (черновик для юриста, не готовый договор)

Цель: юзер владеет результатом генерации; сервис и/или партнёр получают **ограниченную лицензию на дистрибуцию**, не забирая права навсегда.

Это не замена юристу по IP / IT для СНГ. Ниже — структура, что обычно собирают.

### Какие документы

1. **Пользовательское соглашение / оферта** (при регистрации и при каждом релизе — ссылка + чекбокс).  
2. **Лицензия на результат генерации** (можно внутри оферты): что юзер получает (личные права / коммерция / можно ли перепродавать).  
3. **Поручение / лицензия на дистрибуцию** (отдельный блок или экран при «Отправить»): юзер поручает сервису передать трек партнёру и на DSP.  
4. **Договор с дистриб-партнёром** (B2B): кто licensor в фиде, AI-политика, роялти, takedown.  
5. При выплатах юзеру — **оферта выплат / налоговый статус** (самозанятый, ИП и т.д.) — отдельно, когда появятся деньги.

### Что должно быть написано простыми словами (смысл клауз)

| Тема | Смысл |
| --- | --- |
| Кому права | Права на сгенерированный трек (в объёме, который допускает закон и модель ИИ) переходят / принадлежат пользователю |
| Что даёт юзер нам | Неисключительная лицензия: хранить, обрабатывать, отправлять партнёру и на выбранные площадки, обновлять и снимать релиз |
| Срок лицензии | Пока релиз на площадках / пока юзер не запросил takedown + разумный срок на исполнение |
| AI-disclosure | Трек создан с помощью ИИ; юзер это подтверждает |
| Гарантии юзера | Нет чужих семплов, чужого голоса, чужого текста без прав; идея/промпт — его ответственность |
| Имя на площадках | Указывается псевдоним / имя, которое задал юзер |
| Роялти | Кому идут стримы (юзеру минус комиссия сервиса/партнёра) — цифры в оферте |
| Takedown | Юзер может снять; сервис может снять при нарушении / claim / требовании DSP |
| Возраст / дееспособность | Только 18+ (или как решит юрист) |
| Партнёр | Мы можем привлекать сублицензиата-дистрибьютора |

### Как встроить в продукт

1. При первом входе — принятие оферты (как обычно).  
2. На `/release` перед «Отправить» — короткий текст + чекбокс: «Права остаются у меня; поручаю сервису выложить трек на выбранные площадки». Ссылка на полный текст.  
3. В Java писать факт согласия: `user_id`, `generation_id`, версия оферты, timestamp, список площадок.  
4. Партнёру отдавать только после этого согласия.

### Практические шаги

1. Зафиксировать продуктовую модель одной фразой для юриста: *«AI-генератор; права на трек у пользователя; сервис по поручению пользователя доставляет на DSP через партнёра; бренд сервиса на витрине DSP не обязателен»*.  
2. Найти юриста по IP / digital / музыке (СНГ + понимание зарубежных DSP).  
3. Параллельно RFP партнёрам: «end-user is rights holder; we need distribution license flow».  
4. Не копировать оферту Suno/DistroKid один в один — модели прав и AI у всех разные.  
5. Пока текстов нет — «Отправить» не включать.

## Списки white-label (2026)

Критерий: инфраструктура под **вашим** брендом (портал / API), а не DistroKid-стиль «артист идёт к ним». Списки публичные; цены и AI-политику всегда перепроверять в RFP. СНГ (Яндекс / VK / Звук) у всех уточнять отдельно.

### A. Серьёзный shortlist для нас (писать первыми)

| Партнёр | Тип | Заметки |
| --- | --- | --- |
| [LabelGrid](https://labelgrid.com/) | Independent, публичный API | Цены открыты; API / white-label addendum; удобно разработчикам |
| [limbo/](https://www.limbomusic.com/) | Independent, modular B2B | REST + white-label + QC; меньше «витринных» DSP, зато прямые контракты |

### B. Другие настоящие / близкие к WL

- **Labelcamp** (IDOL) — бэк-офис дистриба, крупные каталоги  
- **AudioSalad** (SESAC) — доставка и каталог, branded dashboard  
- **Sounds.co / Random Sounds** — LATAM-фокус, Spotify Preferred  
- **Vydia** (gamma) — branded platform + rights/monetization  
- **Horus Music** — «свой дистриб» под ключ  
- **Tuned Global**, **SpaceMedia**, **DIG DIS**, **VerseOne Pro**, **DistroDirect**, **Royalti.io** — встречаются в обзорах WL; глубину API и DSP сверять сами  

### C. Не white-label (не путать)

DistroKid, TuneCore, CD Baby, Symphonic, Ditto, Amuse, LANDR, RouteNote, UnitedMasters, ONErpm, Stem, EMPIRE, AWAL — дистриб **под своим** брендом для артистов. Для кнопки «Выпустить» внутри нашего приложения обычно не то.

### D. Локальный / СНГ охват

Отдельно у любого кандидата: **Яндекс Музыка, VK Музыка, Звук**, при необходимости KION / ADV. У мировых пакетов СНГ часто через субдистриба или отсутствует. Локальных «чистых» WL под СНГ в публичных списках мало — это вопрос в RFP, не готовый пункт меню.

## Что делать по шагам

1. **Зафиксировать продукт v1**  
   Сингл из готовой генерации (без отдельной загрузки файла). Кто правообладатель (пользователь / сервис). В первой версии только стриминг или ещё UGC (TikTok / Instagram / YouTube Content ID).

2. **Юридический каркас до питча**  
   Оферта / лицензия: согласие на дистрибуцию, AI-disclosure, запрет чужих семплов и чужих голосов, право снять релиз. Без этого партнёр часто не подпишет.

3. **Shortlist 3–5 и один RFP**  
   Одним письмом всем. Вопросы:
   - политика на fully AI / AI-assisted музыку;
   - список DSP, особенно СНГ;
   - глубина white-label (UI, письма, «Provided by…» на YouTube);
   - API: upload → validate → queue → status / webhooks, выдача ISRC/UPC;
   - роялти: % партнёра, срок выплат, payout в РФ / СНГ;
   - кто модерирует релиз до отправки;
   - takedown / claim / бан аккаунта;
   - цена: setup + monthly + per release + %;
   - минимальный объём релизов.

4. **Пилот на одном партнёре**  
   10–50 тестовых релизов, узкий набор площадок, ручная проверка доставки. Фронт уже фасад; ключи и статусы — в Java, не в браузере.

5. **Интеграция**  
   Java создаёт релиз у партнёра, заливает audio / cover / metadata, принимает статусы. Фронт на `/release` включает «Отправить» и показывает статусы.

6. **Мягкий запуск**  
   Сначала бета / внутренние. Потом снять «Скоро» у Релиза. Экономику релиза (отдельно от paywall на скачивание) решить после цифр партнёра.

## Черновик RFP (можно слать)

> We are building a CIS-focused AI music product. Users generate songs in our app and should be able to release them to streaming platforms under our brand (white-label / distribution API). We will not operate our own DSP contracts.  
> Please confirm: (1) policy for fully AI-generated / AI-assisted music; (2) DSP coverage including Yandex Music, VK Music, Zvuk plus global majors; (3) white-label branding depth; (4) REST/API + webhooks for release status, ISRC/UPC; (5) royalty share, payout timelines and methods for CIS creators; (6) moderation / takedown process; (7) pricing (setup, monthly, per-release, revenue share) and minimum volume.  
> We need a pilot of 10–50 releases before production.

## Риски

| Риск | Почему больно |
| --- | --- |
| Запрет AI у партнёра или DSP | Весь поток релизов встаёт |
| Смена владельца партнёра | Новые правила для AI-платформ |
| Утечка чужого бренда | В письмах / YouTube видно не нас |
| Роялти и выплаты в СНГ | Задержки, комиссии, нет удобного payout |
| Ответственность за контент | Чужой голос / семпл → claim на аккаунт дистриба |
| Бан фида на DSP | Плохой поток AI режет все наши релизы |
| Дорогой минимум enterprise | Fee несоразмерен стадии продукта |
| Нет локальных площадок | Мир есть, Яндекс / VK нет — дыра для аудитории |
| Vendor lock-in | Каталог и коды у партнёра; смена = миграция |

## Практичная рекомендация

- Параллельно писать 3 enterprise (Revelator / limbo / LabelGrid или FUGA) и 1–2 AI-friendly API.
- Решающий фильтр: **AI ok + СНГ DSP + API статусов + белый бренд**.
- Пока договора нет — «Отправить» на `/release` оставлять выключенным.
- Не дублировать дистрибуцию вторым бэкендом пользователей: контракт и ключи живут в Java.

## Статус UI на момент документа

- Черновики релиза в `localStorage` браузера.
- Каталог площадок в UI — основной пакет (стриминг + UGC), не полный «150+».
- Иконки известных брендов — Simple Icons (CC0); редкие площадки — цветные буквы.
- Отправка на модерацию / DSP ещё не подключена.
